**NetShift** - маршрутизатор трафика для OpenWrt. Направляйте нужные ресурсы в туннель, а остальное - напрямую. Открытое ПО на базе [sing-box](https://github.com/SagerNet/sing-box).

Это форк [itdoginfo/podkop](https://github.com/itdoginfo/podkop), значительно расширяющий функциональность.

> [!WARNING]
> Проект находится в стадии бета-версии. Возможны ошибки, нестабильная работа и существенные изменения функциональности.

---

## Функции

- [x] **Маршрутизация по доменам и подсетям** - нужное в туннель, остальное напрямую<br><sub>VLESS · Shadowsocks · Trojan · Hysteria2 · VMess · SOCKS · готовые community-списки</sub>
- [x] **Subscription URL** - ссылки подписки от провайдера с автообновлением и автовыбором лучшего сервера<br><sub>любая подписка remnawave · 3x-ui · marzban · github · форматы base64 / URI / Clash / Xray JSON</sub>
- [x] **Несколько подписок и фильтры** - несколько фидов в одной секции, фильтр серверов по ключевым словам (include / exclude)<br><sub>объединение без дублей · регистронезависимо · работает и по эмодзи</sub>
- [x] **Группировка серверов** - по флагу страны или по префиксу имени, с авто-выбором «⚡ Самый быстрый» среди всех групп<br><sub>URLTest внутри группы · URLTest над группами · ручной выбор сохранён</sub>
- [x] **Переключаемое ядро sing-box** - стабильное ↔ sing-box-extended ↔ extended lite прямо из веб-интерфейса<br><sub>клиентский транспорт xhttp · lite-сборка для устройств с малой Flash · самовосстановление и автооткат · установка в один клик</sub>
- [x] **Самообновление из веб-интерфейса** - проверка и установка обновлений NetShift прямо из LuCI<br><sub>асинхронно · бэкап конфига · без риска «окирпичивания»</sub>
- [x] **Веб-интерфейс LuCI** - дашборд, менеджер компонентов, диагностика и настройки без ручной правки конфигов<br><sub>статус серверов · проверка соединения · логи · вкладки-карточки</sub>
- [x] **IPv6, блокировка DoH, глобальный прокси** - полная маршрутизация v6 через туннель, защита DNS роутера, режим «весь трафик в туннель»<br><sub>v6 tproxy / DNS / FakeIP · DNS через прокси · фоновый watchdog sing-box</sub>
- [x] **Kill switch (fail-closed)** - при перезапуске NetShift или падении sing-box проксируемый трафик блокируется, а не уходит напрямую, и DNS не откатывается, пока туннель не поднимется<br><sub>подсети + FakeIP + fully_routed · окна рестарта сервиса и краш-восстановления sing-box</sub>
- [x] **Автоматическая миграция** - обновление со старого podkop переносит конфиг без перенастройки

## Вещи, которые необходимо знать перед установкой

<details open>
<summary><b>Системные требования</b></summary>

- OpenWrt **24.10** или выше (поддерживаются и сборки на `opkg`/`.ipk`, и новые на `apk`/`.apk` - OpenWrt 25.12+).
- Минимум **25 МБ** свободного места. Устройства с флеш-памятью 16 МБ не поддерживаются.
- На устройстве: `sing-box >= 1.12.0`, `jq >= 1.7.1`, `coreutils-base64 >= 9.7` (ставятся как зависимости пакета).

</details>

<details>
<summary><b>Обновления и конфигурация</b></summary>

- При обновлении **обязательно** [очищайте кэш LuCI](https://podkop.net/docs/clear-browser-cache/).
- После обновления проверяйте конфигурацию - она может меняться между версиями.
- При старте NetShift модифицирует конфигурацию Dnsmasq.
- NetShift изменяет конфигурацию sing-box. Если используете собственную - заранее сохраните её.

</details>

<details>
<summary><b>Ограничения и особенности</b></summary>

- Если установлен **Getdomains**, его [необходимо удалить](https://github.com/itdoginfo/domain-routing-openwrt?tab=readme-ov-file#скрипт-для-удаления).
- **Dashboard** работает только по HTTP (особенность Clash API). По HTTPS или через домен может быть недоступен.

</details>

<details>
<summary><b>Поддержка и диагностика</b></summary>

- [Руководство по диагностике](https://podkop.net/docs/diagnostics/)
- Актуальные изменения - в [Telegram-чате](https://t.me/netshift_chat/2) (читайте закреплённые сообщения).
- При проблемах оставляйте технически грамотный фидбэк в GitHub Issues и Telegram-чате.

</details>

<details>
<summary><b>Миграция с podkop (0.8.0) и смена формата конфига (0.7.0)</b></summary>

**0.8.0 - переименование в NetShift.** Пакет теперь `netshift` (бинарь `/usr/bin/netshift`), конфиг - `/etc/config/netshift`, LuCI-приложение - `luci-app-netshift`. При обновлении старый конфиг `/etc/config/podkop` автоматически мигрируется в `/etc/config/netshift`, резервная копия сохраняется в `/etc/config/podkop.bak.pre-netshift`. туннель продолжит работать без перенастройки.

**0.7.0 - несовместимый формат конфига.** Старые значения несовместимы - нужно настроить заново. Скрипт установки обнаружит старую версию и предложит сделать это автоматически. Вручную:

```sh
mv /etc/config/netshift /etc/config/netshift-070
wget -O /etc/config/netshift https://raw.githubusercontent.com/yandexru45/netshift/refs/heads/main/netshift/files/etc/config/netshift
# затем настроить заново через LuCI или UCI
```

</details>

## Установка NetShift

Полная инструкция - в [документации](https://podkop.net/docs/install/).

Для установки и обновления достаточно одного скрипта:

```sh
sh <(wget -O - https://raw.githubusercontent.com/yandexru45/netshift/refs/heads/main/install.sh)
```

Интерфейс появится в LuCI: **Services → NetShift**.

<details>
<summary><b>Готовые community-списки</b></summary>

Готовые наборы доменов/подсетей, которые можно добавить в секцию через `community_lists` (в UI - чекбоксами). Списки обновляются автоматически:

`russia_inside` · `russia_outside` · `ukraine_inside` · `geoblock` · `block` · `porn` · `news` · `anime` · `youtube` · `hdrezka` · `tiktok` · `google_ai` · `google_play` · `hodca` · `discord` · `meta` · `twitter` · `cloudflare` · `cloudfront` · `digitalocean` · `hetzner` · `ovh` · `telegram` · `roblox`

```sh
uci add_list netshift.my_sub.community_lists='youtube'
uci add_list netshift.my_sub.community_lists='telegram'
uci commit netshift
```

</details>

<details>
<summary><b>Настройка подписки (Subscription URL) через UCI</b></summary>

Поддерживаются любые подписки (remnawave · 3x-ui · marzban · github) в форматах **base64 · список URI · Clash · Xray JSON**, в т.ч. **gzip-сжатые** ответы. При скачивании подписки отправляются заголовки:

| Заголовок | Значение |
|---|---|
| `User-Agent` | подбирается автоматически (`singbox/<версия>` или клиентский, см. формат) |
| `X-HWID` | уникальный идентификатор роутера |
| `X-Device-OS` | `OpenWrt Linux` |
| `X-Device-Model` | модель роутера |
| `X-Ver-OS` | версия ядра |

```sh
uci set netshift.my_sub=section
uci set netshift.my_sub.connection_type='proxy'
uci set netshift.my_sub.proxy_config_type='subscription'
uci set netshift.my_sub.subscription_url='https://your-provider.com/api/sub'
uci set netshift.my_sub.subscription_update_interval='1h'
uci add_list netshift.my_sub.community_lists='russia_inside'
uci commit netshift
```

**Интервал автообновления** задаётся в каждой секции отдельно (`30m | 1h | 3h | 6h | 12h | 1d`, по умолчанию `1h`) и не зависит от порядка секций в конфиге: на каждое значение создаётся своё cron-задание, которое обновляет только секции с этим интервалом. `/usr/bin/netshift subscription_update` без аргумента обновляет все секции, с интервалом (`subscription_update 1d`) - только секции с ним (для `1d` можно добавить время: `subscription_update 1d 04:30`). Значение вне списка (например, вписанное в UCI руками `2h`) трактуется как `1h` с предупреждением в логе - секция не выпадает из обновления; вызов `subscription_update` с неизвестным интервалом обновляет все секции.

**Время ежедневного обновления** (`subscription_update_interval='1d'`) задаётся опцией `subscription_update_time` в формате `ЧЧ:ММ` (`00:00`-`23:59`, местное время роутера; в веб-интерфейсе - поле «Время обновления», оно видно только при интервале «Каждый день»). По умолчанию `09:52` - так, как задание работало раньше, поэтому существующие конфиги не меняются. Секции с одним временем делят одно cron-задание, с разным - у каждого времени своё (`subscription_update 1d 04:30` обновляет только секции на 04:30). Расписание собирается из UCI при каждом запуске сервиса, поэтому время сохраняется после перезапуска и обновления пакета. Не выбирайте время, на которое приходится другое задание NetShift (`:00`/`:30` при обновлении раз в 30 минут, `:17` при часовом, `:13` у обновления списков и т. д.; учитывается и час): два обновления одновременно могут пересечься - в этом случае в лог пишется предупреждение с ближайшей свободной минутой. Поле «день месяца» у заданий в crontab не сравнивается, поэтому задание обновления списков раз в 3 дня может дать предупреждение и в день, когда оно не запускается. Если время указано у секции с интервалом не «Каждый день», оно игнорируется, и это тоже попадает в лог.

```sh
uci set netshift.my_sub.subscription_update_interval='1d'
uci set netshift.my_sub.subscription_update_time='04:30'
uci commit netshift
```

**Несколько подписок** в одной секции - добавьте `subscription_url` списком (в UI - поле с «+»); все фиды скачиваются и объединяются в один набор узлов без дублей:

```sh
uci add_list netshift.my_sub.subscription_url='https://provider-a.com/sub'
uci add_list netshift.my_sub.subscription_url='https://provider-b.com/sub'
```

Без группировки (`subscription_group_mode=off`), когда живые узлы есть хотя бы у двух подписок, у каждой такой подписки есть свой блок на дашборде и свой «Самый быстрый» (`⚡ <имя>`). Если живые узлы остались только у одной подписки, дашборд выглядит как раньше, без блоков. Общий «Самый быстрый» по всем узлам остаётся выбором по умолчанию. Имя подписки берётся из `#фрагмента` ссылки, а без него из хоста. Фрагмент на сервер не отправляется и в ключ кеша не входит, поэтому переименование подписки не сбрасывает её кеш и не вызывает повторного скачивания. Ссылки, в которых уже был фрагмент, после обновления NetShift скачиваются заново один раз (раньше фрагмент входил в ключ кеша). Файлы кеша ссылок, которых больше нет в списке секции, удаляются при сборке конфига. `+` во фрагменте читается как пробел, как в именах узлов из ссылок. Если у двух подписок одинаковое имя (например, один хост без фрагментов), ко второму добавляется её номер в списке: `provider-a.com (2)`. Две ссылки, которые отличаются только фрагментом, считаются одной подпиской: её узлы добавляются один раз:

```sh
uci add_list netshift.my_sub.subscription_url='https://provider-a.com/sub#Мой VPN'
```

**Фильтр серверов** по ключевым словам - белый/чёрный список (регистр не важен, работает и по эмодзи):

```sh
uci add_list netshift.my_sub.subscription_filter_include='🇩🇪'
uci add_list netshift.my_sub.subscription_filter_exclude='trial'
```

**Группировка серверов** - собирает узлы в URLTest-группы и добавляет авто-выбор «⚡ Самый быстрый» среди всех групп (при ≥2 группах он же выбор по умолчанию; ручной выбор группы сохраняется):

```sh
# off | country (по флагу страны) | prefix (по первым N символам имени)
uci set netshift.my_sub.subscription_group_mode='country'
# для prefix: сколько первых символов имени брать (по умолчанию 2)
uci set netshift.my_sub.subscription_group_prefix_len='2'
```

**Предпочтительный формат** - для панелей, которые отдают нужные узлы (например xhttp / Hysteria2) только под определённым клиентом:

```sh
# auto | xray (Xray JSON, UA как у Happ) | singbox
uci set netshift.my_sub.subscription_format_preference='auto'
```

**Подписки по IP-хосту и «кривой» HTTPS** - можно указать подписку с IP вместо домена (например `https://22.23.43.52:2096/sub/xxxx`); для панелей с самоподписанным / несовпадающим сертификатом включите небезопасный TLS:

```sh
uci set netshift.my_sub.subscription_allow_insecure='1'
```

Ручное обновление подписки и очистка кеша:

```sh
/usr/bin/netshift subscription_update          # перечитать и применить
# Очистка кеша всех подписок и повторное скачивание - кнопка во вкладке «Диагностика»
```

</details>

<details>
<summary><b>Менеджер компонентов: ядра sing-box (extended / extended lite) и самообновление</b></summary>

Вкладка **Менеджер компонентов** в LuCI управляет NetShift и ядром sing-box в одном месте - четыре карточки: **NetShift** / **sing-box (stock)** / **sing-box (extended)** / **sing-box (extended lite)**. Установленная версия видна сразу, статус (актуально / устарело / не установлено) и кнопка «Проверить обновление» - по нажатию.

**Переключение ядра** между стабильным sing-box и сборками **sing-box-extended**:

- **Install extended** - расширенное ядро (даёт клиентский транспорт **xhttp**, только клиентский режим). Также поддерживается **VMess**.
- **Install lite** - лёгкая сборка extended для устройств с малой Flash (подробнее ниже).
- **Install stable** - вернуться на стабильное ядро.

Смена ядра безопасна: перед переключением проверяется и при необходимости чинится связь, делается бэкап; при сбое - **автооткат**, роутер никогда не остаётся без рабочего ядра. По умолчанию стоит стабильное - extended и lite включаются по желанию.

**sing-box extended lite** - третья опция ядра: лёгкая сборка extended-ядра для устройств с малой Flash (роутеры на 16-128 МБ). Полный extended занимает ~105 МБ, lite - **~15 МБ** (Pure ELF) или **~10 МБ** (UPX-сжатый). Сборка ведётся из тегов [shtorm-7/sing-box-extended](https://github.com/shtorm-7/sing-box-extended) с урезанным набором build-тегов; релизы публикуются в нашем репозитории [yandexru45/sing-box-extended-lite](https://github.com/yandexru45/sing-box-extended-lite), каждая установка проверяется по **SHA-256** (сверка с `sha256sums.txt` релиза). Lite-версия отличима по суффиксу `-lite` в номере (например `1.14.1-extended-2.7.2-lite`).

Все ключевые для NetShift фичи сохранены: VLESS+Reality+Vision, VLESS Encryption (mlkem), XHTTP, VMess, Hysteria2/TUIC, Clash API, TPROXY, FakeIP. Вырезано серверное и тяжёлое: tailscale / openvpn / cloudflared / acme / gvisor и др. - из заметного: **WireGuard в userspace-режиме не работает** (только system-интерфейс).

Вариант сборки выбирается автоматически: при **≥64 МБ** свободного места на `/` ставится Pure ELF, иначе - UPX-сжатый. Ручной выбор:

```sh
uci set netshift.@settings[0].sing_box_lite_build='elf'      # или 'compressed'
uci commit netshift
```

UPX-бинарник распаковывает себя в память при каждом запуске: на устройствах с RAM **<256 МБ** включите zram-swap (установщик предупредит кодом `upx_ram_spike`). Поддерживаемые архитектуры: arm64, amd64, armv7, mips-softfloat, mipsle-softfloat - на остальных карточка lite неактивна. Ручные community-установки lite (обёртки в духе MANCrimSon/EikeiDev) распознаются и показываются как установленный lite.

**Самообновление NetShift** - кнопка обновления прямо из веб-интерфейса: асинхронно, с бэкапом конфига, проверкой фактической версии после установки и без риска «окирпичивания». Русская локализация обновляется только если уже установлена.

<details>
<summary><b>Дополнительные настройки (IPv6, блокировка DoH, глобальный прокси, DNS через прокси, Reality ML-KEM)</b></summary>

Опции секции `settings` (`0` - выкл, `1` - вкл); опции отдельных секций, например `reality_mlkem`, описаны ниже:

```sh
# Полная маршрутизация IPv6 через туннель (v6 tproxy / DNS / FakeIP). По умолчанию выкл.
# Правила маршрутизации действуют на оба входа (IPv4 и IPv6); отдельного резолва имени
# перед маршрутизацией для IPv6-входа нет (имя, которое локальный DNS не знает или
# отдаёт неверно, всё равно доходит до прокси, как и по IPv4). FakeIP для IPv6 -
# 2001:2::/48 (вне ULA, который режет защита dnsmasq);
# при смене диапазона кеш sing-box один раз сбрасывается (выбранные серверы - по умолчанию).
uci set netshift.settings.enable_ipv6='1'

# Блокировка DoH: клиенты в сети не обойдут DNS роутера через DNS-over-HTTPS
# (режет известные DoH-эндпоинты IPv4 + IPv6 на уровне маршрутов sing-box).
uci set netshift.settings.block_doh='1'

# Глобальный прокси: ВЕСЬ трафик через выбранный outbound (а не только избранное).
# Только при явном включении - иначе действует выборочная маршрутизация.
uci set netshift.settings.global_proxy='1'

# DNS через прокси (detour): DNS-запросы идут через туннель.
uci set netshift.settings.dns_via_outbound='1'

# Блокировать QUIC (заставляет приложения откатываться на TCP/TLS).
uci set netshift.settings.disable_quic='1'

# Пропускать BitTorrent мимо туннеля: торрент-трафик (TCP и UDP, определяется
# сниффингом протокола) идёт напрямую, минуя прокси/VPN. По умолчанию выкл.
# Нужно тем, у кого провайдер блокирует подписку за торренты.
uci set netshift.settings.exclude_bittorrent='1'

# Kill switch (fail-closed): пока NetShift не перехватывает трафик - перезапуск
# сервиса, падение и восстановление sing-box - трафик к проксируемым
# назначениям (подсети, FakeIP, fully_routed) блокируется вместо утечки
# напрямую, а DNS не возвращается на прямые резолверы, поэтому проксируемые
# домены тоже ждут. Пока sing-box не работает, DNS недоступен (в том числе для
# прямых сайтов); прямой непроксируемый трафик не затрагивается, пока sing-box
# запущен. Загрузка роутера до первого старта сервиса не закрывается.
# По умолчанию выкл.
uci set netshift.settings.block_leaks='1'
# Адрес, по которому дашборд измеряет задержку серверов (по умолчанию
# https://www.gstatic.com/generate_204; в некоторых регионах он медленный или
# заблокирован). Нужен http(s)-адрес; иначе берётся значение по умолчанию, а в
# лог пишется предупреждение. В веб-интерфейсе - «Адрес теста задержки», вкладка «Дополнительно».
uci set netshift.settings.latency_test_url='https://cp.cloudflare.com/generate_204'

uci commit netshift
```

**Отключение kill switch.** Опция держит DNS на DNS-inbound sing-box, пока тот не поднялся, и оставляет таблицу `NetShiftGuard` активной. Поэтому после ручной остановки сервиса (`service netshift stop`) DNS и проксируемый трафик останутся заблокированными, а если watchdog перестанет перезапускать sing-box после нескольких падений подряд — это состояние сохранится. Чтобы вернуть прямой интернет, выключите опцию и перезапустите сервис:

```sh
uci set netshift.settings.block_leaks='0'
uci commit netshift
/etc/init.d/netshift restart
```

Kill switch блокирует только то, что NetShift сам отправил бы в туннель. Локальные и служебные адреса (`192.168.0.0/16`, `10.0.0.0/8` и т. п.), проброшенные порты (DNAT), адреса и устройства из bypass, а при `exclude_ntp` и NTP идут напрямую и с включённой опцией, как и без неё.

При удалении и при обновлении пакета kill switch снимается сам (prerm возвращает DNS и удаляет таблицу `NetShiftGuard`), иначе роутер остался бы без DNS до ручного запуска сервиса. Настройка при обновлении сохраняется, и следующий старт сервиса снова включает блокировку. Смена ядра sing-box из веб-интерфейса и `install.sh` снимают блокировку на время загрузки пакетов, если без этого до репозитория не достучаться, и возвращают её при следующем старте сервиса.

**Откат на версию без kill switch.** Старая версия про таблицу `NetShiftGuard` не знает и при остановке её не удалит. Перед откатом выключите опцию и перезапустите сервис (команды выше) либо удалите таблицу вручную: `nft delete table inet NetShiftGuard`.

**Компоненты через прокси.** `download_components_via_proxy='1'` (веб-интерфейс - вкладка «Списки», «Скачивать компоненты через Proxy/VPN») направляет загрузки компонентов с GitHub - ядро sing-box-extended/lite, пакеты NetShift и запросы информации о релизах - через локальный сервисный прокси в секцию, выбранную в `download_lists_via_proxy_section` (она общая со скачиванием списков, но сами флаги независимы: загрузка списков идёт через прокси только при `download_lists_via_proxy`). Стабильное ядро sing-box ставится из фидов OpenWrt и через этот прокси не идёт. Если секция не выбрана, удалена или отключена, запросы к сервисному прокси отклоняются и загрузка компонентов идёт напрямую. Нужно, когда GitHub заблокирован или режет адрес роутера. Прокси пробуется первым, при ошибке загрузка повторяется напрямую; пока sing-box не запущен (например, при замене ядра), прокси недоступен и загрузка идёт напрямую.

**Обход sing-box (bypass).** Сейчас исключение работает внутри sing-box: трафик помечается, попадает в tproxy и только там уходит напрямую. Для исключённых адресов это лишняя нагрузка, особенно при глобальном прокси (когда в sing-box идёт вообще всё). Два переключателя убирают такой трафик из sing-box на уровне nftables:

- `bypass_singbox='1'` на секции типа «Исключение» (веб-интерфейс - «Обходить sing-box»): подсети этой секции (community-списки подсетей, удалённые, пользовательские и локальные списки) попадают в набор `netshift_bypass`, который возвращается раньше меток по назначению (метки по источнику `fully_routed_ips` ставятся раньше него), и трафик на эти адреса не заходит в sing-box. Если один и тот же список лежит и в bypass-секции, и в proxy-секции, исключение выигрывает - так же, как исключающее правило стоит перед правилами секций внутри sing-box. Домены обойти так нельзя (у домена нет фиксированного адреса), они по-прежнему проходят через sing-box.
- `settings.bypass_excluded_ips='1'` (вкладка с «Routing Excluded IPs»): устройства из `routing_excluded_ips` отправляются напрямую, минуя sing-box, раньше остальных меток, в том числе раньше `fully_routed_ips` и глобального прокси. Исключение: трафик устройства на адреса FakeIP (проксируемые домены) по-прежнему маркируется в sing-box, где правило `routing_excluded_ips` отправляет его напрямую, потому что пакет на FakeIP-адрес вне sing-box был бы потерян. Если список `routing_excluded_ips` пуст, в лог пишется предупреждение (обходить нечего). Отключённые секции в расчёт не берутся.

Правила bypass ставятся первыми в цепочках prerouting и output, так что исключение выигрывает у любых меток, как и раньше внутри sing-box. Без этих опций (по умолчанию и у всех существующих конфигов) правила nft не меняются.

```sh
uci set netshift.<секция-исключение>.bypass_singbox='1'
uci set netshift.settings.bypass_excluded_ips='1'
**Интервал проверок URLTest.** Опция секции `urltest_check_interval` (вкладка «Подписка», «URLTest Check Interval») принимает `30s`, `1m`, `3m` (по умолчанию), `5m`, `10m`, `20m`, `30m`, `1h`, `6h`, `24h` и `off`. `off` - проверить серверы один раз при запуске и больше не повторять (для sing-box это интервал в год). Чем реже проверки, тем меньше трафика на каждый сервер группы.

```sh
uci set netshift.<секция>.urltest_check_interval='30m'
uci commit netshift
```

**Приоритетный выбор сервера.** Опция секции `priority_mode='1'` (selector, urltest и подписки; веб-интерфейс - вкладка «Подписка», «Предпочитать серверы по порядку списка») выбирает **первый работающий** сервер в порядке списка и возвращается к более приоритетному, как только он снова отвечает. URLTest, наоборот, выбирает самый быстрый и порядок не учитывает. Проверку делает монитор по часам, каждые 30 секунд (`settings.priority_check_interval`, не меньше 10): список прокси берётся из Clash API один раз за цикл, затем по очереди измеряется задержка серверов до первого ответившего (не больше 10 проб, у каждой запроса есть таймаут) и переключается селектор секции. На весь цикл отводится не больше 15 секунд, чтобы не задерживать слежение за sing-box; секции, не уместившиеся в бюджет, проверяются первыми в следующем цикле. Опция действует только на proxy-секции (иначе - предупреждение в лог). Группы (urltest, группы по странам) пропускаются, поэтому для сгруппированных подписок режим ничего не делает (один раз на секцию об этом пишется предупреждение в лог). Отключённые секции не проверяются. Если не отвечает ни один из первых серверов, выбор не меняется и пишется предупреждение.

```sh
uci set netshift.<секция>.priority_mode='1'
uci set netshift.settings.priority_check_interval='30'

**Каскад подключений.** Опция секции `outbound_detour_section` (веб-интерфейс - вкладка «Подключение», «Подключаться через другую секцию») строит цепочку: соединения с серверами этой секции идут через outbound выбранной секции (двойной прыжок, `detour` в sing-box). Работает для ссылки, selector/urltest и подписок; своё `detour` в `outbound_json` не перезаписывается, а `outbound_json` с группой selector/urltest не каскадируется (участники такой группы могут принадлежать другим секциям): такая секция отклоняется, как и при другой неисправной цепочке. Общий `direct-out` detour не получает никогда. Цепочка может быть длиннее двух секций. Если цепочку построить нельзя (секция-цель не существует, не proxy/VPN, недоступна, цепочка зациклена), трафик секции **отклоняется**, а не уходит напрямую в обход первого прыжка, и в лог пишется ошибка. Это относится и к секции с `global_proxy`: при её неисправной цепочке весь остальной трафик, не попавший под другие правила, отклоняется (а не уходит напрямую, как при упавшей подписке).

```sh
uci set netshift.<секция>.outbound_detour_section='<секция-цель>'

**Несколько DNS-серверов (приоритет / параллельно).** Основной сервер (`dns_server`) остаётся первым, дополнительные задаются списком `dns_pool_server` в формате `схема://хост[:порт][/путь]` (схема - `udp`, `tcp`, `dot`, `doh`, `doh3`, `doq`; путь - только для `doh`/`doh3`). Режим - `dns_pool_mode`:

- `single` (по умолчанию) - только основной сервер, всё как раньше;
- `fallback` - по приоритету: основной, затем список по порядку; следующий опрашивается, если предыдущий не ответил за `dns_pool_timeout` или вернул ошибку (SERVFAIL/REFUSED);
- `race` - параллельно: запрос уходит всем серверам сразу, берётся первый пригодный ответ (`NOERROR` или `NXDOMAIN`), остальные запросы отменяются.

```sh
uci set netshift.settings.dns_pool_mode='race'
uci add_list netshift.settings.dns_pool_server='doh://dns.google/dns-query'
uci add_list netshift.settings.dns_pool_server='dot://dns.quad9.net'
uci add_list netshift.settings.dns_pool_server='udp://1.1.1.1'
uci set netshift.settings.dns_pool_timeout='2s'   # на один сервер; по умолчанию 2s
uci commit netshift
```

**DNS-секция (split DNS).** Секция с типом подключения `dns` отдаёт домены из своих списков отдельному DNS-серверу (`dns_type`: `udp`, `tcp`, `dot`, `doh`, `doh3`, `doq`; `dns_server`; необязательно `dns_detour_section` - опрашивать сервер через outbound другой секции, при недоступном outbound - напрямую). Домены получают настоящие адреса, а не FakeIP, и через туннель не идут: это DNS для трафика, который и так выходит напрямую (корпоративная или локальная зона и т. п.). Используются только домены из списков, подсети игнорируются: секция только с подсетями (или со списками без доменов) пропускается с предупреждением, потому что её правило без условия перехватило бы весь DNS роутера. Сервер можно задать голым IPv6-адресом; отключённая секция пропускается; секцию нельзя выбрать как прокси для загрузки списков (у неё нет outbound). Версия NetShift без этой опции не знает тип подключения `dns`: перед понижением версии такие секции нужно удалить. Если домен есть и в списке proxy/VPN-секции, он остаётся на её FakeIP-пути. При включённом глобальном прокси такой трафик попадёт в него, если не добавить секцию-исключение.

```sh
uci set netshift.corp='section'
uci set netshift.corp.connection_type='dns'
uci set netshift.corp.dns_type='dot'
uci set netshift.corp.dns_server='dns.corp.example'
uci add_list netshift.corp.local_domain_lists='/etc/netshift/corp-domains.lst'
uci commit netshift
```

**Перенаправление DNS по зонам.** Список `dns_forward` на вкладке «Настройки - DNS» отправляет запросы зоны прямо на выбранный DNS-сервер, как строка `list server '/ru/77.88.8.8'` в конфиге dnsmasq. Раньше такие строки приходилось держать при включённой галочке «Dont Touch My DHCP»: на время работы NetShift переносит список `server` dnsmasq в сторону. Теперь записи хранятся в конфиге NetShift и добавляются в dnsmasq при запуске, а при остановке уходят вместе с остальными настройками NetShift. Запись - `зона сервер` (допустима и форма dnsmasq `/зона/сервер`), сервер - IP-адрес, при необходимости с `#портом`; зона охватывает и все поддомены, самая точная побеждает. Некорректные записи пропускаются с предупреждением в логе. Имена этих зон получают настоящие адреса, а не FakeIP, поэтому по домену они не маршрутизируются: домен из списков секции внутри такой зоны даёт предупреждение в логе (домены из подключаемых списков не проверяются). При включённой «Dont Touch My DHCP» записи не применяются. Если нужен разбор по доменам с сохранением правил sing-box, используйте DNS-секцию выше.

```sh
uci add_list netshift.settings.dns_forward='ru 77.88.8.8'
uci add_list netshift.settings.dns_forward='corp.example 10.0.0.53#5353'
uci commit netshift
```

В веб-интерфейсе есть готовые серверы для каждого протокола (Google, Cloudflare, Quad9, AdGuard, Yandex, Mullvad: UDP, TCP, DoT, DoH, DoH3, DoQ), список принимает и любые свои записи.

Нужен **sing-box 1.14.0 и новее** (режимы собираются из DNS-правил `evaluate`/`respond`/`race`); на более старом ядре список игнорируется с предупреждением в логе. Всего до 8 серверов вместе с основным, лишние и некорректные записи пропускаются с предупреждением. При включённом «DNS через прокси» все серверы пула идут через тот же outbound, имена хостов резолвятся через bootstrap DNS. В режиме `fallback` при недоступном основном сервере каждый новый запрос ждёт `dns_pool_timeout` до перехода к следующему (результат здоровья серверов не запоминается), поэтому для надёжного отказа лучше `race` или короткий таймаут (`500ms`).

**Устройства сети.** Вкладка **«Устройства»** на странице NetShift показывает устройства LAN (по данным DHCP/ARP) и для каждого позволяет выбрать: «по умолчанию (по спискам)», «напрямую» (адрес попадает в «Routing Excluded IPs» / `routing_excluded_ips`) или «всё через секцию» (адрес попадает в «Fully Routed IPs» / `fully_routed_ips` этой секции; доступны proxy- и VPN-секции, у которых есть это поле; отключённые секции не предлагаются как цель, но устройство, записанное в такой секции, показывается с пометкой). Вкладка не пишет конфиг сама, а меняет значения этих полей на соседних вкладках, поэтому изменение сохраняется обычной кнопкой «Сохранить и применить» и не затирается устаревшим значением. Устройство всегда лежит ровно в одном месте; адреса из списков, которых сейчас нет в сети, остаются в таблице, чтобы их можно было вернуть к умолчанию. Подсеть из «Fully Routed IPs» можно переносить между секциями, но не в «напрямую» (там допускаются только отдельные адреса). IPv6-адрес устройства показывается только при включённом `enable_ipv6`.

**Перехват DNS клиентов.** Опция `dns_hijack='1'` («Отправлять DNS-запросы LAN на роутер» на вкладке «Настройки - Сеть») перенаправляет обычные DNS-запросы (UDP и TCP порт 53), которые приходят с интерфейсов-источников на чужой адрес, на DNS самого роутера. Нужна, когда у устройства DNS прописан вручную (например, `8.8.8.8`): оно обходит роутер, не получает FakeIP-ответов, и маршрутизация по доменам для него не работает. Запросы к самому роутеру не трогаются (правило `fib daddr type local return` стоит первым), DNS поверх TLS/HTTPS не перехватывается. Правила лежат в отдельной цепочке `dns_hijack` таблицы NetShift (nat, `prerouting`, приоритет `dstnat`) и исчезают вместе с таблицей при остановке. При включённой «Dont Touch My DHCP» DNS роутера не отдаёт FakeIP, поэтому перехват меняет только того, кто отвечает; об этом пишется предупреждение в лог.

**Список серверов на дашборде.** Серверы секции показываются списком (одна строка на сервер: название, тип, задержка, пометка «Активен» у выбранного; длинный список прокручивается) вместо плиток. Кнопка «Плитки» / «Список» переключает вид, кнопка «Сортировка по пингу» упорядочивает серверы по задержке (быстрые сверху, без замера - в конце, запись «Fastest» остаётся первой). Выбор хранится в браузере (`localStorage`), на роутере ничего не меняется.
**Фильтры серверов подписки по стране.** К фильтрам по ключевым словам добавлены `subscription_filter_include_countries` и `subscription_filter_exclude_countries` - списки двухбуквенных кодов стран (`NL`, `DE`, регистр не важен). Страна определяется по флагу-эмодзи в названии сервера, поэтому код превращается в такой же фильтр по ключевому слову и объединяется с остальными: «оставить» - подходит любое совпадение, «исключить» - сервер отбрасывается при любом. Некорректный код пропускается с предупреждением. Фильтры по регулярным выражениям не добавлялись: в jq на OpenWrt нет regex, а ключевые слова и страны покрывают те же случаи.

```sh
uci add_list netshift.<секция>.subscription_filter_include_countries='NL'
uci add_list netshift.<секция>.subscription_filter_exclude_countries='RU'
uci set netshift.<секция>.geoip_flags='1'
uci commit netshift
```

**GeoIP-флаги.** Серверы без флага в названии нельзя сгруппировать и отфильтровать по стране, а на дашборде они выглядят безлико. `geoip_flags='1'` на секции (веб-интерфейс - «Определять страну по IP (GeoIP)», вкладка «Подключение», любой тип прокси) один раз определяет страну такого сервера по адресу (домен резолвится через bootstrap DNS, адреса идут пачками по HTTPS на `api.country.is`). Для подписки флаг ставится перед названием, после чего группировка, фильтры по странам и дашборд работают как для серверов с флагом. Для собственных ссылок (одиночная ссылка, selector, urltest, их текстовые варианты, outbound JSON) теги в sing-box фиксированы, поэтому страна запоминается по тегу outbound в `/tmp/sing-box/geoip-links.json` (пересобирается при каждой сборке конфига) и дашборд подставляет флаг перед названием; ссылка, у которой флаг уже есть в названии (после `#`, для vmess - в `ps`), не отправляется. Результаты хранятся в `/etc/netshift/geoip.json` (найденная страна - 30 дней, неудача - сутки), поэтому следующие сборки не делают запросов. Адреса серверов секции уходят внешнему сервису, поэтому опция выключена по умолчанию; частные адреса (IPv4 и IPv6: приватные и link-local диапазоны, ULA, loopback, CGNAT, multicast) и адреса из диапазонов FakeIP (берутся из констант) не отправляются; если имена серверов не резолвятся (нет сети при загрузке роутера, медленный DNS), поиск прерывается после 10 неудач или 60 секунд, ничего не запоминается, и повтор будет при следующей сборке конфига. Файлы `/etc/netshift/geoip.json` и `/tmp/sing-box/geoip-links.json` доступны только владельцу.

Самообновление NetShift теперь проверяет все скачанные пакеты до установки первого: размер не меньше 2 КБ, для `.ipk` - целостность gzip-архива, для `.apk` - сигнатура `ADB` или gzip. Страница с ошибкой лимита GitHub или обрезанный файл под именем пакета останавливают обновление до любых изменений в системе, а не после замены ядра пакета.

**Проверка окружения.** В диагностике появился блок «Окружение» (команда `netshift check_environment`, ответ - JSON). Он показывает то, что молча ломает перенаправление: включённый Flow Offloading (программный или аппаратный: установленные соединения проходят мимо хуков netfilter с метками NetShift), часы роутера (дата раньше 2025 года - ошибка; расхождение больше пяти минут с заголовком `Date` ответа сайта - предупреждение, это нужно TLS и Reality) и глобальный адрес IPv6 при выключенной обработке IPv6. Единственное обращение к сети - один HEAD-запрос для сверки часов; без интернета расхождение просто не определяется. Настройки роутера блок не меняет.

**Логин для Mixed Proxy секции и защита от конфликта портов.** Прокси секции (`mixed_proxy_enabled`, порт `mixed_proxy_port`, по умолчанию 2080) раньше был открыт всем в локальной сети. Теперь можно потребовать логин: `mixed_proxy_auth='1'`, `mixed_proxy_username`, `mixed_proxy_password` (в sing-box это `users` mixed-входа; пароль хранится в UCI как введён). Если логин запрошен, но задан не полностью, прокси не создаётся вовсе: открытый прокси там, где задумывался закрытый, - неверный способ ошибиться. Кроме того, два прокси на одном порту или прокси на порту самого NetShift (сервисный прокси 4534, tproxy 1602/1603, Clash API 9090, DNS 53/5354) раньше заставили бы sing-box отвергнуть всю конфигурацию; теперь такой прокси пропускается с предупреждением, а остальное запускается. У секции без прокси функция больше ничего не делает и не пишет в журнал. Без `mixed_proxy_auth` поведение прежнее.

```sh
uci set netshift.main.mixed_proxy_enabled='1'
uci set netshift.main.mixed_proxy_port='2080'
uci set netshift.main.mixed_proxy_auth='1'
uci set netshift.main.mixed_proxy_username='me'
uci set netshift.main.mixed_proxy_password='secret'
**Префиксы в списках доменов.** Запись `example.com` по-прежнему означает домен и все его поддомены. Три префикса (как в v2ray) сужают или расширяют совпадение: `full:host` - только этот хост, без поддоменов; `keyword:text` - любое имя, содержащее текст; `regex:шаблон` (допустимо и `regexp:`) - регулярное выражение, в нём не должно быть пробелов и запятых. Префиксы работают в своих доменах секции (динамический и текстовый список), в локальных и удалённых текстовых списках; в доменной части `.srs`/`.json` списков они уже поддерживаются самим sing-box. Шаблон проверяется ядром: некорректное выражение пропускается с предупреждением в логе, а не ломает конфигурацию. Битые шаблоны ищутся делением списка пополам (несколько битых из тысяч стоят десятки запусков `sing-box`, а не по одному на строку); после 20 неверных шаблонов в одном списке остальное игнорируется с одним предупреждением, а без `sing-box` шаблоны `regex:` не проверить, и они игнорируются (тоже одно предупреждение). Регистр внутри `regex:` сохраняется (`\D` и `\d` - разные вещи), остальное приводится к нижнему.

```sh
uci add_list netshift.<секция>.user_domains='full:exact.example.org'
uci add_list netshift.<секция>.user_domains='keyword:tracker'
uci add_list netshift.<секция>.user_domains='regex:^ads[0-9]+\.example\.com$'
uci commit netshift
**Куда пойдёт запрос.** Команда `netshift check_route <домен|IP> [адрес-клиента]` и блок «Куда пойдёт запрос» на вкладке «Диагностика» показывают, какая секция (или прямой путь, или блокировка) обработает домен или IP и каким DNS-сервером он будет разрешён. Правила берутся из сгенерированной конфигурации sing-box и проверяются самим ядром (`sing-box rule-set match`), поэтому списки, регулярные выражения и бинарные наборы ведут себя так же, как при работе. Удалённые наборы скачиваются во временный кэш (`/tmp/netshift-route-check`), через сервисный прокси, если он включён для списков. Правила, зависящие от адреса клиента (устройства, bypass), без адреса пропускаются, ответ помечается `incomplete`; укажите адрес устройства вторым аргументом, и они будут учтены. Условия, которые нельзя воспроизвести без живого трафика (порты, определение протокола), тоже пропускаются с этой пометкой. Ответ - JSON:

```sh
netshift check_route youtube.com
netshift check_route 203.0.113.9 192.168.1.50
**Фильтры серверов подписки по протоколу, транспорту и защите.** К фильтрам по названию и стране добавлены фильтры по тому, как сервер подключается: `subscription_filter_{include,exclude}_{protocols,transports,security}`. Протокол - тип узла (`vless`, `vmess`, `trojan`, `shadowsocks` (`ss`), `hysteria2` (`hy2`), `tuic`, `socks` и др.), транспорт - `tcp` (у узла нет транспорта), `ws`, `grpc`, `http`, `httpupgrade`, `xhttp` (узлы с транспортом `quic` из JSON-подписки фильтр понимает, но в списке интерфейса такого варианта нет), защита - `reality`, `tls` или `none`. Правила: сервер должен пройти **каждый** заданный список (оставить - он входит в список; исключить - не входит), и фильтр по названию тоже; регистр не важен, неизвестное значение пропускается с предупреждением. Фильтр работает до выдачи тегов и до проверки ядром, поэтому убранные серверы не попадают ни в селектор, ни в urltest, ни на дашборд. Без заданных списков набор не меняется.

```sh
uci add_list netshift.<секция>.subscription_filter_include_protocols='vless'
uci add_list netshift.<секция>.subscription_filter_exclude_transports='grpc'
uci add_list netshift.<секция>.subscription_filter_include_security='reality'
**EDNS Client Subnet по WAN.** К ручному вводу `dns_client_subnet` добавлено автоопределение: флаг `dns_client_subnet_auto='1'` (в интерфейсе - «Определять EDNS Client Subnet по WAN» на вкладке «Настройки - DNS») берёт подсеть из WAN-интерфейса. Публичный адрес интерфейса используется как есть; если адрес серый (RFC 1918, CGNAT 100.64.0.0/10), внешний адрес один раз узнаётся через этот интерфейс (`api.country.is`, запасной - `api.ipify.org`), запоминается в `/etc/netshift/ecs-external.json` вместе с локальным адресом и спрашивается заново только при его смене. В ECS уходит /24 найденного IPv4-адреса. При нескольких WAN (зона `wan`, интерфейс с маршрутом по умолчанию первым) можно закрепить интерфейс опцией `dns_client_subnet_interface`; пусто - первый работающий. Если адрес определить не удалось, используется введённое вручную значение (или ничего). Подсеть вычисляется при запуске и перезагрузке службы. `netshift get_wan_addresses` показывает интерфейсы и подсеть каждого (JSON), найденные подсети предлагаются в выпадающем списке поля ECS. Без флага поведение прежнее.

```sh
uci set netshift.settings.dns_client_subnet_auto='1'
uci set netshift.settings.dns_client_subnet_interface='wan'   # необязательно
uci commit netshift
```
**Единый список DNS-серверов.** На вкладке «Настройки - DNS» основной сервер и дополнительные объединены в один упорядоченный список «DNS-серверы» (`scheme://host[:port][/path]`, схемы `udp`, `tcp`, `dot`, `doh`, `doh3`, `doq`); первый - основной. Хранение не изменилось: первый элемент записывается в `dns_type` и `dns_server`, остальные - в список `dns_pool_server`, поэтому настройки старых версий открываются как есть, переносить ничего не нужно, а понижение версии сохраняет рабочую конфигурацию. Режим «Несколько DNS-серверов» (`dns_pool_mode`: первый сервер / приоритет / параллельно) по-прежнему выбирается отдельно; при добавлении второго сервера в режиме «Только первый сервер» интерфейс сам переключает его на приоритет. Основным теперь может быть любой из шести транспортов (раньше - только `udp`, `dot`, `doh`); проверка DNS в диагностике умеет `tcp` (`dig +tcp`), а для `doh3` и `doq`, которых нет в `dig`, судит по ответу DNS-входа sing-box. Блокировка DoH предупреждает и об основном `doh3`.
**Вкладка «Соединения».** Живая таблица соединений sing-box (Clash API через бэкенд, интерфейс по-прежнему общается только с `netshift`): назначение (хост и порт, а при их отсутствии адрес), протокол, источник, путь (группа → узел), трафик, возраст. Можно искать, сортировать (новые / по трафику / по адресу), закрыть одно соединение или все сразу; таблица обновляется раз в 3 секунды, пока вкладка на экране. Закрытое соединение приложение откроет заново, если оно ему ещё нужно. Команды: `netshift clash_api get_connections` (не больше 300 новейших, `CONNECTIONS_LIST_CAP`; в ответе только нужные поля), `clash_api close_connection <id>` и `clash_api close_connections`. Идентификатор проверяется до запроса (только hex и дефисы).
**Устройства: только локальная сеть и статические аренды DHCP.** На вкладке «Устройства» остались только хосты с адресом в подсетях локальной сети (сети зоны `lan` брандмауэра, а если зоны нет - сети с DHCP-сервером); «соседи» провайдера по WAN, которые роутер видит в таблице соседей, больше не показываются. Адреса, уже внесённые в списки маршрутизации, остаются видимыми и для не подключённых устройств. В таблицу добавлены поиск и колонка «Аренда DHCP»: устройству можно закрепить адрес (статическая аренда - обычная запись `config host` в `/etc/config/dhcp`, та же, что показывает LuCI в «DHCP и DNS»), изменить адрес и имя или освободить аренду. Это отдельные действия, не часть «Сохранить и применить»: бэкенд меняет только `dhcp` и перечитывает dnsmasq (`reload`), настройки dnsmasq, которыми управляет NetShift, не затрагиваются. Проверяется MAC, формат имени, принадлежность адреса локальной сети и отсутствие конфликта с другой арендой. Записи, созданные NetShift, называются `netshift_<mac>`; чужие записи с тем же MAC редактируются на месте. Команды бэкенда:

```sh
netshift get_lan_info
netshift dhcp_host_set aa:bb:cc:dd:ee:ff 192.168.1.50 laptop
netshift dhcp_host_remove aa:bb:cc:dd:ee:ff
```
**Уведомление о новых версиях.** На дашборде появляется рамка «Доступна новая версия» (NetShift и, для расширенных ядер с GitHub, sing-box-extended / lite), когда на GitHub есть версия новее установленной. Роутер не опрашивает GitHub по расписанию: при открытии дашборда интерфейс читает последний ответ из `/tmp/netshift-update-notice.json` (`netshift get_update_notice`, без обращения к сети) и, если ответ старше суток (`UPDATE_NOTICE_TTL`), запускает одну фоновую проверку (`netshift refresh_update_notice`), по её окончании читает ответ снова. Если GitHub недоступен, прежний ответ остаётся, и роутер не повторяет запрос при каждой загрузке страницы. Стоковое ядро не проверяется (для этого пришлось бы обновлять индексы пакетов). Выключается опцией `update_notice='0'` («Уведомлять о новых версиях» на вкладке «Списки и обновления»); ничего не устанавливается.
**Снимки настроек.** При каждом запуске службы с конфигурацией, которую принял sing-box, NetShift копирует `/etc/config/netshift` в `/etc/netshift/snapshots/<время>-auto.conf`; последние десять хранятся, неизменённая конфигурация нового снимка не создаёт. Это точка возврата после изменения, которое сломало службу. Блок «Снимки настроек» на вкладке «Диагностика» показывает список, сохраняет снимок вручную и восстанавливает выбранный (с перезапуском службы). Перед восстановлением текущие настройки сохраняются как `before-restore`, так что возврат можно отменить; изменения, ожидающие применения в LuCI, сбрасываются. Файл должен читаться UCI и содержать секцию `settings`, идентификатор проверяется до обращения к файлу. Снимки доступны только root и не содержат ничего, кроме самих настроек. Команды: `netshift config_snapshot save [manual]`, `config_snapshot list`, `config_snapshot restore <id>`. Автоматического отката при ошибке нет: возврат выполняется явным действием.
**Уход с мёртвого сервера, выбранного вручную.** Сервер, выбранный в селекторе секции вручную, остаётся выбранным, даже когда перестаёт отвечать, и секция молча не работает. Опция секции `pin_guard='1'` («Уходить с мёртвого сервера, выбранного вручную») включает проверку в мониторе: на каждом цикле (интервал `priority_check_interval`, 30 секунд по умолчанию) выбранный сервер проверяется той же пробой через Clash API, что и в режиме «по порядку списка»; после трёх неудач подряд (`PIN_GUARD_FAILURES`) селектор переключается на автоматическую группу секции (самый быстрый сервер), событие пишется в журнал и показывается на дашборде в течение суток (`netshift get_pin_guard_events`, последние десять в `/tmp/netshift-pin-guard.json`). Если выбрана сама автоматическая группа, ничего не делается; нужна urltest-группа, поэтому опция работает для списков URLTest и подписок, а в секции с `priority_mode` она не действует (там своё правило). По умолчанию выключено.
**Тест скорости DNS.** Кнопка «Проверить серверы» на вкладке «Настройки - DNS» (`netshift dns_benchmark [сервер...]`, без аргументов - основной сервер и список дополнительных) показывает, за сколько миллисекунд каждый DNS-сервер отвечает именно с этого роутера: скорость зависит от провайдера и маршрута, а не от таблицы «лучших серверов». Каждому серверу задаётся один вопрос через `dig`, все сразу, так что проверка занимает не дольше самого медленного ответа (не более трёх секунд). Имена серверов DoT и DoH сначала разрешаются через bootstrap DNS, чтобы замер не зависел от проверяемого резолвера; для DoT/DoH используется `+tls-hostname`. DoH3 и DoQ в `dig` отсутствуют и не замеряются. Проверяется не больше двенадцати серверов, ответ - JSON `{"results":[{"server","ms"}]}` (`null` - нет ответа). При включённой опции «Route main DNS through proxy/VPN» серверы опрашиваются не с роутера, а через туннель: резолвер внутри него (например, `172.31.x.x` на сервере с Marzban) для самого роутера не существует. Для этого на несколько секунд запускается второй sing-box: у него по одному локальному `direct`-входу на сервер (`127.0.0.1:192xx`, `override_address`/`override_port` - адрес и порт сервера), все выходы - через тот самый outbound, которым идёт основной DNS (группа селектора или urltest раскрывается до выбранного сейчас сервера по Clash API, цепочка `detour` переносится), а `dig` опрашивает эти порты, так что замер включает туннель, как и настоящие запросы. Ответ содержит поле `via` (`tunnel` или `direct`); если временный экземпляр не удалось запустить (нет sing-box, Clash API не отвечает, outbound не найден), серверы опрашиваются с роутера, как раньше. Ничего не меняется: результат помогает выбрать порядок серверов в режиме приоритета.

> По умолчанию NetShift гонит в sing-box **только** проксируемые подсети/домены, остальное - напрямую (выборочная маркировка). Режим «весь трафик в туннель» включается **только** опцией `global_proxy`.

**Опция секции: Reality и Xray-core 26.9.8+ (постквантовый key share).** Сервер REALITY на Xray-core **26.9.8 и новее** (в 3x-ui - начиная с 3.8.0) отвергает клиента, который не присылает key share `X25519MLKEM768`; стандартный sing-box вырезает его из ClientHello, и подключение падает с `reality verification failed`. В sing-box-extended **2.7.2+** (включая lite) для этого есть опция, а в NetShift - галка секции **«Reality: постквантовый key share (X25519MLKEM768)»** (`reality_mlkem`, по умолчанию выкл.). Она добавляет `support_x25519mlkem768` в Reality-outbound'ы секции (ссылки, selector/urltest и подписки; свой `outbound_json` не трогается). Нужен отпечаток `chrome` (`fp=chrome`, у остальных отпечатков ML-KEM нет): у ссылок и узлов подписки с другим отпечатком (или без него) поле не добавляется, а для ссылки об этом пишется предупреждение в лог. Ссылка может сказать это сама: параметр `support-x25519mlkem768=true` (его пишет 3x-ui во все REALITY-ссылки, формат тот же, что у mihomo `reality-opts`) включает поле для этого outbound'а без галки секции, а `support-x25519mlkem768=false` запрещает его даже при включённой галке. На ядре без этой опции такая ссылка даёт предупреждение в лог, что серверу нужен sing-box-extended 2.7.2+. У узлов подписки формата sing-box уже стоящее поле `support_x25519mlkem768` на ядре, которое его знает, сохраняется (`true` и `false`), при включённой галке `true` получают все узлы с отпечатком `chrome`, кроме помеченных `false`; у узлов с другим отпечатком и на ядре без опции поле удаляется. Для секций с `outbound_json` и не-прокси секций галка не применяется (с предупреждением в логе). На старых серверах включать не нужно: они могут не пройти рукопожатие. На стандартном ядре и на extended до 2.7.2 опция игнорируется с предупреждением в логе, потому что такое ядро не знает поле и отвергло бы весь конфиг.

```sh
uci set netshift.<секция>.reality_mlkem='1'
```

Отдельную секцию можно временно отключить, не удаляя её настроек (в веб-интерфейсе - галка «Отключить секцию» на вкладке «Дополнительно»). Отключённая секция полностью игнорируется: без маршрутизации, списков и обновления подписок.

```sh
uci set netshift.<секция>.disabled='1'   # отключить (='0' или удалить опцию - включить обратно)
uci commit netshift
```

</details>

│       ├── etc/init.d/netshift     # procd init-скрипт
│       └── usr/
│           ├── bin/netshift        # Точка входа CLI (диспетчер команд)
│           └── lib/                # constants, helpers, nft, rulesets,
│                                   #   sing_box_config_*, updater, logging
│
├── luci-app-netshift/              # LuCI веб-интерфейс
│   ├── Makefile
│   ├── cache-bust.sh               # при сборке пакета: view/netshift -> view/netshift_<хеш>
│   ├── htdocs/.../view/netshift/   # main.js (автоген) + hand-written views (в установленном пакете - view/netshift_<хеш>/)
│   ├── po/                         # Переводы (генерируются из fe-app)
│   └── root/                       # menu.d · acl.d · uci-defaults
│
├── fe-app-netshift/                # TypeScript-исходник для main.js (tsup)
│   ├── src/netshift/               # fetchers · methods · services · tabs
│   ├── src/{validators,helpers,icons,partials}
│   └── locales/                    # Исходные переводы (netshift.pot / .po)
│
├── sdk/                            # Базовые образы OpenWrt SDK
├── Dockerfile-ipk · Dockerfile-apk # Сборка пакетов
└── install.sh                      # Установщик + миграция с podkop
```

## Build Artifacts

Пакеты собираются в Docker-образах OpenWrt SDK (`.ipk` - 24.10, `.apk` - 25.12) и публикуются как релиз при push git-тега ([`.github/workflows/build.yml`](.github/workflows/build.yml)).

| Пакет | Формат | Назначение |
|---|---|---|
| `netshift` | `.ipk` / `.apk` | Бэкенд: CLI, init-скрипт, библиотеки, UCI-конфиг |
| `luci-app-netshift` | `.ipk` / `.apk` | Веб-интерфейс LuCI |
| `luci-i18n-netshift-ru` | `.ipk` / `.apk` | Русская локализация интерфейса |

Локальная сборка:

```sh
# ipk (OpenWrt 24.10, opkg)
docker build -f Dockerfile-ipk --build-arg NETSHIFT_VERSION=0.9.1 -t netshift:ipk .

# apk (новые сборки OpenWrt 25.12+, apk)
docker build -f Dockerfile-apk --build-arg NETSHIFT_VERSION=0.9.1 -t netshift:apk .
```

> Требуется sing-box >= 1.12.0, jq >= 1.7.1 и coreutils-base64 >= 9.7 на целевом устройстве.
